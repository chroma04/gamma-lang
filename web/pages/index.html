Systems programming with everything in the signature.

Gamma is a language meant to replace C. A function’s inputs are its parameters, its failures are in E!T, a missing result is ?T, and its context — the allocator, input and output, the clock, the outside world — is its effect set, written after needs. Algebraic effects supply that context, so it is explicit without being passed around by hand, and tests can replace it.

fs    :: import "std/fs"
arena :: import "std/arena"

// Counts the lines of a file. The signature says everything it touches.
count_lines :: fn(path: string) -> fs.ReadError!usize needs Fs + Alloc {
    text := try fs.read_all(path)          // from the current allocator
    defer free(text)
    n: usize = 0
    for b in bytes(text) { if b is '\n' { n += 1 } }
    return n
}

main :: fn() -> fs.ReadError!() needs Fs + Alloc + Out {
    scratch := arena.new()                 // you choose where memory comes from
    defer scratch.deinit()
    with scratch.allocator() {
        print("{} lines\n", try count_lines("README.md"))
    }
}

test "counts lines" {                      // tests get an in-memory file system
    ok(fs.write_all("notes.txt", "one\ntwo\n"))
    expect_eq(ok(count_lines("notes.txt")), 2)
}
  • Inputsare the parameters. Top-level bindings are constants; a mutable global is a #global, and touching one is the Sys effect, visible in the signature.
  • Failuresfs.ReadError!usize is a count or an error, and try passes the error up. No errno, no exceptions.
  • Absenceis ?T. Pointers are never null unless their type says so.
  • Contextneeds Fs + Alloc lists everything the function may touch. Calling print from it is a compile error, and the test swaps in an in-memory file system without changing a line.

What it keeps from C, and what it removes

Five principles, each of which the specification turns into concrete rules.

Data is bytes you can lay out

Structs are laid out as in C, values copy as bytes, and you choose every size and alignment. No hidden fields, no object headers, no garbage collector.

Cost is visible where it is paid

Allocation is an effect, so a function that allocates says so. Memory comes from whatever allocator the caller installed — the heap, an arena, a fixed buffer — and is freed with defer.

Context is an effect

What C does with globals, callbacks and void*, setjmp and hand-written state machines — logging, I/O, iteration, early exit, coroutines — is a handler installed with with.

Mistakes are rejected

No implicit numeric conversions, no fallthrough, no precedence traps such as x & 1 == 0. Overflow traps unless you choose to wrap (+%), saturate (+|) or check (+?).

Every rule is local

Reading a declaration tells you the worst case. A function whose effects have no esc or ctl operation always returns to its caller.

C is a neighbour

Call C functions and use C types directly, export Gamma functions to C, and link with C sources and libraries from a package manifest.

Effects in one screen

An effect declares operations. A function that performs one says so with needs; a with block above it decides what the operations do.

connect below neither knows nor cares where its messages go. The same mechanism carries the allocator, standard output, the clock, randomness and the file system, which is how a test can run the same code against a fake clock and an in-memory disk.

The effects chapter explains the three kinds of operations: fn, esc and ctl.

Log :: effect {
    log: fn(msg: string)
}

connect :: fn(host: string) -> bool needs Log {
    Log.log(host)
    return host.len > 0
}

main :: fn() needs Out {
    // In production: print the messages.
    printer :: handler Log { log(msg) => print("log: {}\n", msg) }
    with printer { _ = connect("example.org") }

    // In a test, or when it does not matter: drop them.
    quiet :: handler Log { log(msg) => {} }
    ok := with quiet { connect("") }
    print("ok = {}\n", ok)
}
Run in the playground

One tool

The reference implementation is a single binary. The interpreter starts at once; the C and Cranelift back ends give the same results, faster.

gamma run main.gm                         # check and interpret: no C compiler needed
gamma build main.gm -o main               # compile through C: Debug, Checked, Fast or Safe (Fil-C)
gamma run --backend=cranelift main.gm     # compile with Cranelift: builds several times faster
gamma build --target=wasm32-wasi main.gm  # cross-compile, WebAssembly included
gamma test --coverage                     # tests get a fake clock and an in-memory file system
gamma fmt · lint · fix                    # one style, warnings with fixes, compiler-suggested edits
gamma new · add · fetch · update          # packages: git, path and archive dependencies
gamma lsp · doc · repl                    # editor support, API documentation, a REPL

Install

Prebuilt binaries for Linux, macOS and Windows are attached to each release. The installer puts gamma and its standard library in ~/.gamma:

curl -fsSL https://github.com/chroma04/gamma-lang/releases/latest/download/install.sh | sh

On Windows, in PowerShell: irm https://github.com/chroma04/gamma-lang/releases/latest/download/install.ps1 | iex. To build from source you need Rust 1.95 or newer: cargo build --release. Native builds need a C compiler; the interpreter does not.
