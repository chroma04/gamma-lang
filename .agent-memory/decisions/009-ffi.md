# 009 FFI, #global, calling conventions (M10)
- `Sys`: prelude `pub Sys :: effect {}`; ambient (main may have it); no ops so never performed;
  recorded at #global uses and foreign calls (default effect set {Sys}). Cannot be handled.
- `#global name: T = e` → tir GlobalDef{init, value: ConstValue}; ExprKind::Global(id) is a place;
  every use records {Sys}. Foreign `#global` → init None, value None, link name.
- `x :: foreign "lib" {…}` → synthetic module (DeclValue::Module) whose members are Fn decls
  (FnKind::Foreign{lib, link_name, variadic}; FnDef params/locals filled from the signature) and
  globals. Interpreter can't call C: `gamma run` switches to the C backend when the program has
  foreign fns (decided after analysis); the interpreter traps if it reaches one anyway.
- C calling conventions: a Named or non-capturing Literal fn whose effects ⊆ {Sys} is "plain":
  C signature without hidden (env, cx, inst) params — so it is directly a C callback. Fn pointer
  types with effects ⊆ {Sys} are plain C pointers (§19.1 C-compatible). Effectful fn pointers use
  the hidden convention; widening a plain pointer to an effectful type sets the low bit (all
  generated fns are __attribute__((aligned(4)))), and effectful indirect calls test the bit.
  Closures always call hidden-convention code (plain fns get a thunk gm_thN).
- Foreign symbols are declared under a private C name with an asm label
  (`__asm__(GM_SYM("puts"))`, GM_SYM adds __USER_LABEL_PREFIX__) so they never clash with the
  runtime's libc headers.
- Structs by value: C-compatible struct/#c_union/#bits types get a mirror C type
  (cgen Types::mirror, `gm_csN` with typed fields, _Static_assert on size/align/offsets; #bits →
  its integer). Plain-convention signatures (foreign, exports, plain fns, plain fn-pointer calls)
  use mirrors (`plain_cty`); FnGen::plain_value/gamma_value wrap GM_CONV (memcpy statement expr).
  Verified against real ABIs: div/ldiv returns, cabs/conj (2×f64 = SSE class), cabsf.
