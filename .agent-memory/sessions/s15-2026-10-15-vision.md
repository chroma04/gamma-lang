# s15 (2026-10-15) design review → implementation (PR #38)
User asked for a "vision" interrogation; report docs/design-review.md (removed in s16, record in decisions/025); user then said
"execute the plan in its totality". Done in order S2, S3, S6, S4, S5, S7, S1 (S6 before S4
because rest-arg packing needs simple positional binding).
Lessons:
- Migrations were driven by temporary GAMMA_MIGRATE env hooks in sema that printed byte-offset
  edits (MIGRATE2/DROP/MOVE/QUALIFY/UNWRAP), applied by scratch scripts; hooks removed after.
  Pitfalls: core lib is embedded (include_str!) → rebuild between rounds or offsets go stale;
  same std file reached via different path strings → dedupe by realpath; parse-stage tests
  must not be "migrated" via check (revert tests/conformance/parse); dropping explicit types
  can silently change meaning when only literals determine them (convert to named instead).
- Subagents (sonnet) did guide ch 2–16 review well; one found a spec example error.
