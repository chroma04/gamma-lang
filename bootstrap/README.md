# Bootstrapping gamma

`seed/` holds `gamma`, the Gamma compiler written in Gamma (`compiler/`), as C: the code
that the compiler generates for its own sources, as the translation units that a build of
the compiler compiles (one per source file, and the runtime), each named after the hash of
its text. With it, `gamma` can be built on a
machine that has a C compiler and nothing else.

```sh
bootstrap/build.sh            # writes target/bootstrap/gamma
```

The script compiles the seed (`gamma0`), has `gamma0` build the compiler of the
current sources (`gamma1`), and has `gamma1` build itself, so that the result is the
current compiler as generated by itself. `CC` selects the C compiler (`CFLAGS` are
honored) and `JOBS` the number of units compiled at once (by default the number of
processors).

The compiler is compiled only once on the way: the script compiles the seed's units exactly
as a build of the compiler would, and `gamma0` takes the object of every unit that is
still the same in the current sources instead of compiling it (`GAMMA_UNIT_OBJECTS`, see
`docs/architecture.md`); `gamma1` then finds every object in the cache. With a seed of the
current sources the whole build takes under a minute on four cores; each source file
changed since the seed has its unit compiled once more. Once `target/bootstrap/gamma`
exists, rebuild after a change with
`GAMMA_STD=$PWD/lib/std GAMMA_RUNTIME=$PWD/runtime target/bootstrap/gamma build compiler -o <out>`.

The seed works on every 64-bit little-endian Unix-like system that Gamma supports: Linux
and macOS on x86-64 and AArch64 (CI builds it on each). The compiler asks the system which
one it runs on, so the C does not depend on the machine it was generated on.

## Where the seed comes from

`seed/SOURCE` names the git trees of `compiler/`, `lib/` and `runtime/` the seed was
generated from. The seed is exactly the C that the compiler of those sources, built by
itself, generates for them; nobody edits it. `bootstrap/verify.sh [GAMMA0]` checks this:
it compiles the seed (or uses the given `gamma0`), has the result generate C for the
named trees and compares. CI runs it on x86-64 Linux, where the seed is generated. So
reviewing the seed means reviewing the Gamma sources it names, and each seed is generated
by the compiler of the one before it.

The seed needs refreshing when the compiler's sources stop building with it, that
is, when they start using something the seed's compiler does not have; and it is worth
refreshing when so much has changed since that the build from it has become slow.
`tools/refresh-seed.sh [GAMMA]` regenerates it from the committed sources (see
`docs/contributing.md`). The chain of seeds goes back to the last compiler built by the
Rust reference implementation, whose final state is the git tag `rust-reference-final`; see
"Retiring the reference" in `docs/self-hosting.md`, which also describes the fixed point the
build reaches. The tests of the build from the seed are the `selfhost` suite
(`tools/test.sh selfhost/`) and `bootstrap/verify.sh`.
